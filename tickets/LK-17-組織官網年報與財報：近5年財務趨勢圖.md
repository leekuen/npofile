## 目的（要解決什麼問題）

政府資料只有勸募活動的金額，看不到組織整體一年收多少、花多少、花在哪裡。很多組織會在自己官網公開年報、財務報告（財團法人依財團法人法每年也要做財務報表）。把近 5 年的報告找出來、把關鍵數字整理成同一個格式，組織頁就能畫折線圖，讓捐款人一眼看出這個組織的規模與趨勢。資料架構參照美國 Candid（GuideStar）的組織財務頁：每年一列、收入／支出／資產負債三大塊，加上歷年報告原檔清單。

## 使用角色與情境

- 捐款人／一般大眾：在組織頁點「財務與年報」分頁，看近 5 年收入、支出、淨資產的折線圖與每年數字，點連結看原始報告。
- 管理員／編輯：在後台審核爬蟲從官網抓回來的報告與數字，數字讀錯時直接改；改過的不會被下次爬蟲蓋掉。

- 問（agent 代決）：收 3 年還是 5 年？／答：5 年，跟全站「近 5 年」同一個口徑（LK-07，orgs/period.py）／因此：民國 111 年起（2026 年時）。
- 問（agent 代決）：組織官網從哪來？／答：用衛福部公益勸募系統抓到的「官網」欄位（本機 100,062 個組織裡 359 個有）；臉書、IG 這類社群頁不爬（臉書禁止未授權爬取，LK-05 已記錄）／因此：沒官網的組織這次沒有資料，之後要靠其他來源補官網。
- 問（agent 代決）：PDF 怎麼讀出數字？／答：實測創世、兒癌、中信慈善三家的財報 PDF 都是掃描圖、沒有文字層，純文字比對讀不到；改用 Claude（Anthropic API）直接讀 PDF 抽出數字。要設 `ANTHROPIC_API_KEY` 才會讀，沒設就只收報告清單（連結），數字由管理員在後台補／因此：讀數字會產生 API 費用，由後台「每次最多抓幾筆」控制份量。
- 問：為什麼要用 API？不能讓 Claude Code 自己開、自己讀、自己導回去嗎？／答（使用者 2026-11-28 同意做法）：可以，改成也能用訂閱帳號的 Claude Code 在背景讀（`claude -p`），不需要 API 金鑰、不另外付費；有 API 金鑰時仍走 API／因此：正式機的後端映像檔裝 Claude Code，`.env` 設 `CLAUDE_CODE_OAUTH_TOKEN`（`claude setup-token` 拿）就會自動讀；每次爬取最多讀 `FINANCIAL_EXTRACT_MAX_PER_RUN` 份（預設 10），避免用光訂閱額度卡住使用者自己用 Claude。
- 問（agent 代決）：抓回來直接上架嗎？／答：不，非官方來源一律先進待審核（沿用 LK-02、LK-05 的規則）；AI 讀的數字可能讀錯，審核時對照原檔／因此：前台只顯示核准過的。
- 問（agent 代決）：哪些文件算？／答：財務報告／財務報表／會計師查核報告、年報、工作報告／成果報告；工作計畫、預算書（是「打算做」不是「做了什麼」）與捐款徵信名單不收／因此：見〈條件確認〉第 2 條。
- 問：條件與數字口徑可以嗎？／答（使用者 2026-11-27）：全部同意；第 1 條「可以先這樣，但我的確知道有些組織會放在臉書上」；第 3 條「能不能在類似後台的地方提供我審核」／因此：臉書另開後續（要走臉書官方 API 與審核，不爬）；後台審核頁把報告與數字改成看得懂的表格、附原檔連結（見需求細節）。
- 問：呈現方式可以參考 Candid 嗎？／答（使用者 2026-11-27 附 Candid 組織頁截圖：搜尋結果卡片右側列 Total revenue／Total assets、組織頁右欄「Financials Fiscal year 2024」摘要卡＋See more financials）／因此：組織頁右欄加「財務摘要」卡（最近一年總收入、總支出、年底總資產＋看更多連到財務分頁），組織列表卡片加最近一年總收入。
- 問（agent 代決）：誰看得到？／答：報告本來就是組織自己公開在官網的，前台所有人都看得到；只有管理員／編輯能改（見〈需求細節〉欄位權限）。

## 需求細節

- **資料架構（參照 Candid 的 Financials）**：
  - 「年度財務」一年一列：總收入（含捐款收入、政府補助、業務／服務收入、利息與投資收入、其他收入）、總支出（含業務／服務支出、行政管理支出、募款支出）、本期餘絀、年底資產總額、負債總額、淨資產（淨值／基金及餘絀），是否經會計師查核，數字出自哪一份報告。
  - 「報告文件」：年度、種類（財務報告／年報／工作或成果報告）、標題、原檔連結、在官網哪一頁找到的。
- **爬蟲（來源代號 `orgsite`）**：從組織官網首頁出發，跟著「財務、年報、資訊公開、徵信」這類連結最多走兩層、每個網站最多讀 20 頁，同網站內才往下走；遵守 robots.txt、每秒最多一個請求。找到的 PDF／Google 雲端檔案依標題與網址判斷年度與種類。
- **讀數字**：同一個組織同一年優先讀財務報告，沒有才讀年報；同一份檔案讀過就不再讀（省費用）。模型預設 `claude-opus-5-5`，可用 `FINANCIAL_EXTRACT_MODEL` 換。
- **審核**：兩種資料都進「爬蟲資料（審核佇列）」，管理員核准後才上架。後台組織頁可直接新增／修改年度財務；管理員改過的那一年，爬蟲不會再蓋掉。
- **前台**：組織頁新增分頁「財務與年報」（排在「募款與捐款人」後面）：
  - 有 2 年以上數字：折線圖（總收入、總支出、年底淨資產三條線，每條線尾端直接標名稱，不只靠顏色）。
  - 下方表格：每年的總收入、捐款收入、政府補助、總支出、業務支出占比、淨資產，每年附原始報告連結。
  - 報告清單：依年度列出找到的報告檔。
  - 都沒有：空狀態說明「還沒有收錄到這個組織官網公開的財務報告」。
- **Candid 式摘要（使用者 2026-11-27 給的參考）**：組織頁右欄、揭露指數下方加「財務摘要」卡：標題寫「民國 N 年度」，列總收入、總支出、年底總資產，下方「看更多財務資料」連到財務與年報分頁；沒有核准的財務數字就不出這張卡。組織列表卡片在有數字時多一行「總收入 N 萬（民國 N 年度）」。
- **後台審核**：「爬蟲資料（審核佇列）」裡的官網報告與年度財務，改成表格顯示（每個欄位中文名稱＋金額），附「打開原始報告」連結，讓管理員對照 PDF 核准或退回；核准後數字有錯，在組織頁的年度財務區塊直接改（改過會鎖住）。
- 欄位權限：新的，原本沒有（年度財務、報告文件都是新資料）→ 前台所有人看得到核准過的；待審核的只在後台。
- 誰能改：只有管理員／編輯（後台）。

## 數字口徑

| 數字 | 期間與時間欄位 | 時區 | 算哪些（含不含取消、作廢、測試資料） | 同一筆算幾次 | 加總／平均／比例（分母） | 空值 | 跟站上哪個數字同口徑，或差在哪 | 狀態 | 回答日 |
|---|---|---|---|---|---|---|---|---|---|
| 總收入、總支出、本期餘絀 | 組織的會計年度（多數是民國年度 1/1～12/31），以報告寫的年度為準 | 不適用 | 只算核准過的；照報告上「本年度」那一欄，不拿「上年度」比較欄 | 同組織同年度一筆；有多份報告時以財務報告為準 | 照報告原數字（千元會換算成元），不自己加總 | 報告沒列就顯示「—」，不當 0 | 跟「近 5 年實募」不同：實募只算公益勸募活動，總收入是整個組織的收入 | 已確認 | 2026-11-27 |
| 年底淨資產 | 會計年度最後一天的資產負債表 | 不適用 | 同上 | 同上 | 報告上的淨值（基金及餘絀）合計；沒寫就用資產總額減負債總額 | 兩種都算不出來顯示「—」 | 站上沒有同類數字 | 已確認 | 2026-11-27 |
| 業務支出占比 | 同總支出 | 不適用 | 同上 | 同上 | 業務（服務）支出 ÷ 總支出，四捨五入到整數 % | 任一個沒有就顯示「—」 | 站上沒有同類數字；Candid 叫 program expense ratio | 已確認 | 2026-11-27 |

## 這次可能會弄壞什麼

- W1 組織頁原有的三個分頁（募款與捐款人、捐款專案、受裁罰紀錄）與頁首摘要：新增分頁不能讓原本的分頁切換、舊網址 `?tab=` 壞掉。
- W2 既有爬蟲來源（財政部、公益勸募三個來源）與審核佇列：新增資料種類不能讓原本的匯入、核准失敗。
- W3 後台組織編輯頁：多了兩個區塊，原本的存檔與欄位鎖定要照常。

## 邊界（明確不做什麼）

- 不爬臉書、IG；不登入、不繞過驗證碼或 robots.txt。
- 不靠 JavaScript 才顯示內容的網站（例：伊甸、家扶首頁抓不到連結）這次不處理。
- 不把財務資料算進揭露指數（另開票：要改分數口徑，需要案主決定配分）。
- 不從官網以外的地方幫組織找官網網址。
- 臉書粉專上的報告這次不收（使用者知道有組織放在臉書，另開後續：要申請臉書官方 API）。
- 「成果」這次只收成果報告的檔案連結，不從裡面抽服務人次這類成果數字。

## 開發備註（/dev 填寫）

- 實測（2026-11-27）：9 個大型組織官網裡，自閉症基金會（fact.org.tw）、創世、芒草心、fcat2020 首頁兩層內就找得到歷年報告；中信慈善的財報分頁靠 JavaScript 切換、伊甸與家扶首頁是 JavaScript 產生的，抓不到。下載的財報 PDF（創世、自閉症基金會、中信慈善）都是掃描圖、沒有文字層，所以讀數字交給 Claude 讀 PDF。
- 本機試跑 `crawl orgsite --limit 15`（本機 DB、沒設 API 金鑰）：15 個有官網的組織，4 個找到報告、共 29 份進待審核；自閉症基金會 111～113、屏東迦南 111～114 都有財務報告。
- 讀數字的規則（`crawler/npofile_crawler/financials.py` 的 PROMPT）是照自閉症基金會 111～113 年的實際財報對過一輪訂的：合計只抄印出來的數字；業務支出沒有小計時，允許把各業務計畫的支出加總（否則「業務支出占比」幾乎都空白）。**尚未用真的 API 金鑰跑過**（這台電腦沒有金鑰），呼叫格式依 anthropic 2.14 SDK 與測試裡的假回應驗證。
- 實作：爬蟲 `orgsite.py`（找報告）＋`financials.py`（讀數字）；後端 `FinancialYear`、`OrgDocument`、`OrgSiteCheck`（爬取進度，從最久沒爬的開始）；後台組織頁多「年度財務」「官網報告文件」兩區，改過的年度自動鎖住；`prune_old_records` 一併刪 5 年以前的財報與報告；前台組織頁新分頁「財務與年報」＋折線圖 `components/financial-chart.tsx`（無新套件，配色經 dataviz 色盲檢查）。
- 合流（2026-11-27）：先把最新 stage（LK-19/20/24/26 等）併進本分支，資料庫變更改排在 stage 之後：`orgs/migrations/0010_financialyear_orgdocument.py`、`crawling/migrations/0005_orgsitecheck_alter_crawlrecord_kind.py`；與政府補助（grant）、群眾集資（wabay）、排入完整爬取（CrawlRequest）的程式兩邊都保留。合併後後端 152 個測試、爬蟲、部署、前台建置與 lint 全過。
