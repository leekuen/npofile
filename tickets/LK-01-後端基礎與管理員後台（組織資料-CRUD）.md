## 目的（要解決什麼問題）

非營利組織的基本資料、受捐紀錄、捐款專案、受裁罰紀錄散在各個政府網站與組織官網，沒有一個地方能集中維護。
這張票先把「資料放在哪裡、管理員怎麼新增／修改／刪除」做出來，後面的爬蟲（LK-02）、前台（LK-03）、留言（LK-04）都建立在上面。

## 使用角色與情境

- 管理員／編輯：用電腦瀏覽器登入後台（架構圖「登入 → 後台 → 後台 CRUD」），查詢、新增、修改、刪除組織與它底下的四類資料。

## 逼問紀錄

- 問（agent 代決）：後端用 FastAPI 還是 Django？／答：Django＋Django REST framework／因此：架構圖的「後台 CRUD、登入、審核」Django 內建後台就有，不必自己刻；爬蟲同樣是 Python，可以直接共用資料模型。
- 問（agent 代決）：資料庫？／答：正式環境照 AGENTS.md 用 PostgreSQL；本機沒有裝 PostgreSQL，開發時預設用 SQLite，靠環境變數 `DATABASE_URL` 切換／因此：程式不寫死任何一種資料庫。
- 問（agent 代決）：一個組織用什麼當唯一識別？／答：統一編號（8 碼）／因此：財政部名冊與公益勸募系統都有統編，可以把不同來源的資料對到同一個組織。
- 問（agent 代決）：每筆資料要不要記來源？／答：要，每筆受捐、專案、裁罰紀錄都存「來源名稱＋來源網址」／因此：前台能附上出處，資料有爭議時可回查。
- 問（agent 代決）：後台誰看得到、誰能改？／答：只有管理員帳號能登入後台；捐款人帳號（LK-04）進不了後台／因此：見下方欄位權限。

## 需求細節

- 資料分五類，都掛在「組織」底下：
  - 組織基本資料：統一編號、名稱、團體類型、負責人、登記地址、聯絡地址、電話、官網、所在縣市、勸募用途、營運狀態（營運中／已註銷／已撤銷／擅自歇業）、資料來源。
  - 年度募款紀錄（過往受捐款資訊）：年度、實募金額、預募金額、來源。
  - 捐款紀錄（捐款清單，供「大額捐款人排行」）：捐款人名稱、金額、日期、是否匿名、來源。
  - 捐款專案：名稱、服務主題／類別、活動期間、預募／實募金額、許可文號、成果備查日期、結案備查日期、成果說明、來源。
  - 受裁罰紀錄：處分日期、處分機關、處分內容、罰鍰說明、來源。
- 管理員後台：Django 內建後台，以中文介面呈現；組織頁面內嵌四類資料一起編輯；可依統編、名稱搜尋，依縣市、團體類型、營運狀態篩選。
- 管理員帳號用 `createsuperuser` 指令建立；密碼與 `SECRET_KEY` 等祕密全部走環境變數，提供 `server/.env.example`。
- 對前台提供唯讀 API（LK-03 用）：組織列表（分頁）、組織明細（含四類資料）。
- 欄位權限：組織與四類資料都是新的，原本沒有 → 做完：管理員可看可改；公眾／捐款人只能透過前台唯讀 API 看到「組織資料與四類資料」，看不到後台、看不到管理員帳號資訊。捐款紀錄的捐款人若標「匿名」，API 一律回「匿名」不帶真名（同一支判斷，列表、排行、明細都走它）。
- 誰能改：只有管理員／編輯。

## 這次可能會弄壞什麼

不適用：全新專案，還沒有任何既有頁面或功能可以被波及。

## 驗收標準

- [ ] 用管理員帳號登入後台，能新增一個組織，並在同一頁新增年度募款、捐款紀錄、捐款專案、受裁罰紀錄各一筆，存檔後重新打開都在。
- [ ] 後台能用統編或名稱搜到組織，能依縣市、營運狀態篩選。
- [ ] 統一編號不是 8 碼數字時存不進去，並顯示錯誤。
- [ ] 沒登入打開後台會被導到登入頁；捐款人帳號登入後台會被拒絕。
- [ ] 前台 API：組織列表有分頁；組織明細帶出四類資料；匿名捐款不帶真名（自動化測試覆蓋）。
- [ ] 換成 `DATABASE_URL=postgres://…` 時程式不用改（設定讀環境變數，自動化測試確認設定解析）。

## 邊界（明確不做什麼）

- 不做爬蟲（LK-02）、不做前台畫面（LK-03）、不做捐款人帳號與留言（LK-04）。
- 不做多層級管理員權限（全部管理員權限相同）；不做部署。
