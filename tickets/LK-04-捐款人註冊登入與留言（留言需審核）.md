## 目的（要解決什麼問題）

讓捐款人能在組織頁留下經驗與疑問（例如「捐款後有沒有收到收據」「專案成果有沒有公布」），補足官方資料看不到的現場回饋；為了避免惡意攻擊與不實指控，留言要先經管理員審核才公開（架構圖：捐款人 → 登入審核 → 留言）。

## 使用角色與情境

- 公眾／捐款人：在網站註冊帳號、登入，在組織頁的留言區送出留言；送出後看到「審核中」，通過後所有人都看得到。
- 管理員／編輯：在後台留言審核清單核准或退回留言，可附退回原因。

## 逼問紀錄

<!-- 使用者 2026-11-27 指示「全力開發，自己判斷、自己搜尋」，以下全部是 agent 代決。 -->

- 問（agent 代決）：架構圖的「登入審核」是審帳號還是審留言？／答：審留言。帳號註冊後立刻可以登入；每一則留言要管理員核准才公開／因此：註冊門檻低、但公開內容有人把關；組織資訊是公開的，不用登入也能看。
- 問（agent 代決）：註冊要填什麼？／答：Email、顯示名稱、密碼（至少 8 碼）。不做 Email 驗證信（還沒有寄信服務）／因此：列進邊界，之後接寄信服務再補。
- 問（agent 代決）：留言顯示真名還是暱稱？／答：只顯示使用者自己填的「顯示名稱」，Email 永遠不公開／因此：見欄位權限。
- 問（agent 代決）：留言能改能刪嗎？／答：作者可刪除自己的留言；不開放修改（避免審核過後被改成別的內容）；管理員可刪任何留言。

## 需求細節

- 註冊、登入、登出頁面；登入狀態在整個前台都有效（右上角顯示顯示名稱與登出）。
- 組織頁最下方「留言」區：
  - 所有人都看得到已核准的留言（顯示名稱、時間、內容），新的在上。
  - 未登入：看到「登入後才能留言」與登入連結。
  - 已登入：可送出留言（1～1000 字）；送出後自己看得到這則，標「審核中」；被退回的自己看得到「未通過」與原因，其他人看不到。
  - 作者可以刪除自己的留言。
- 後台：留言審核清單（依狀態篩選，預設看待審核），可批次核准／退回、填退回原因；捐款人帳號清單（可停用帳號）。
- 同一個帳號一分鐘內最多送 3 則留言、登入連續失敗有次數限制，避免灌留言與猜密碼。
- 欄位權限：
  - 留言內容、顯示名稱、留言時間：新的，原本沒有 → 做完：已核准的所有人看得到；審核中與未通過的只有作者本人與管理員看得到。
  - 退回原因：新的 → 只有作者本人與管理員看得到。
  - 捐款人 Email：新的 → 只有本人（登入後）與管理員看得到，不出現在任何留言、列表或公開 API。
- 誰能改：留言內容送出後不能改；作者能刪自己的；管理員能核准、退回、刪除任何留言、停用帳號。

## 這次可能會弄壞什麼

## 驗收標準

- [ ] W1 組織頁四個分頁照常切換，加了留言區後版面不跑掉（手機寬度也檢查）。
- [ ] W2 首頁登入前後，搜尋、篩選、換頁都正常，右上角顯示正確的登入狀態。
- [ ] 註冊 → 登入 → 在組織頁送出留言 → 自己看到「審核中」、另一個未登入的瀏覽器看不到。
- [ ] 管理員在後台核准後，未登入的瀏覽器看得到；退回的，作者看到「未通過」與原因。
- [ ] 作者能刪自己的留言，不能刪別人的（API 層也擋，自動化測試）。
- [ ] 公開的留言 API 回應不含任何 Email 欄位（自動化測試）。
- [ ] 一分鐘內第 4 則留言被擋下並提示。

## 邊界（明確不做什麼）

- 不做 Email 驗證信、忘記密碼（需要寄信服務，之後另開票）。
- 不做第三方登入（Google／Facebook）。
- 不做留言回覆、按讚、檢舉。
