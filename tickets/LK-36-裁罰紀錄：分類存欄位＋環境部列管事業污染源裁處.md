## 目的（要解決什麼問題）

組織頁的「受裁罰紀錄」只有公益勸募與臺北市勞動局兩類。環境部每天公開各縣市環保局對列管事業的裁處，而且**每筆都有統一編號**，
不用名稱比對就能對到組織；社福基金會、宗教財團法人、私立學校都會被罰（廢棄物、空污、病媒蚊孳生）。
同時把「這筆是哪一類裁罰」從「看來源名稱猜」改成存在資料表，之後加政府採購停權（LK-38 預定）、司法判決都不用再改判斷邏輯。

## 使用角色與情境

- 公眾／捐款人、記者：組織頁「受裁罰紀錄」看到環保局的裁處，標「環境保護」，有處分日期、裁處書字號、違反法條、罰鍰、違規事實與訴願結果。
- 管理員／編輯：後台組織頁的裁罰紀錄看得到、改得了類別與違反法條；環境部來源要先設好 API 金鑰才會跑。

- 問（agent 自己決定）：違規人名稱、地址存不存？／答：`transgress_name` 可能是個人或工程名稱、地址用不到／因此：不讀、不存（測試檢查）。

## 需求細節

- **分類欄位**：`orgs.Penalty` 加 `category`（預設 `fundraising`，有索引）與 `law`（違反法條，可空白）。migration 依現有來源名稱回填：
  **名稱含「勞動」的都算 `labor`**（LK-29 臺北市勞動局、LK-37 勞動部全國名單都符合），其餘維持 `fundraising`。
- **匯入**：爬蟲在資料裡寫 `category` 的為準；沒寫的照上面同一條規則判斷。API（`PenaltySerializer`）改直接讀欄位，另多給 `law`。
- **環境部來源** `moenv_penalties`：`GET https://data.moenv.gov.tw/api/v2/ems_p_46?api_key=…&format=JSON&limit=1000&offset=N&sort=ImportDate desc`，每秒一個請求，跟 `crawl all` 每天跑。
  - **對組織**：`ban`（統編）在站上組織名冊裡才收（`known_orgs_only`），不做名稱比對、不進審核清單。
  - **欄位**：`penalty_date`→處分日期、`county_name`→處分機關（「臺北市」補成「臺北市政府環境保護局」；金門、連江用各自機關名；其他寫法照原樣）、
    `document_no`→文號、`transgress_law`→違反法條、「違反＋法條；`subject`（主旨）」→處分內容、`penalty_money`→「罰鍰新臺幣 N 元」、
    `openinfor`（違規事實）→處分理由，有訴願／行政訴訟結果附在後面。
  - **同一筆**：管制編號＋裁處機關＋裁處書字號。
  - **只抓新的**：第一次全部回補；之後從「上次完整讀完的那天往前推 120 天」開始，整頁裁處日都早於它就停（接住晚匯入的舊裁處）。
    被筆數或分鐘上限切斷的那次不算讀完，下次照樣全部回補。
- **前台**：組織頁類別標籤加「環境保護」「政府採購停權」（沒對到的顯示「其他裁罰」）；資料說明頁與頁尾資料來源加環境部這份。
- 欄位權限：裁處是環境部公開資料 → 所有人在組織頁看得到（跟現有裁罰同）；只有管理員／編輯能改。違規人名稱、地址不存，哪裡都不會出現。
  新增的 `law` 欄位原本不存在 → 做完是公開 API 看得到（同處分內容）。
