# 實作（general-purpose + isolation:"worktree"；預設 sonnet）

```
【目標與動機】
依票 tickets/<票號-短題.md> 實作：<需求一句話>。
背景：<誰用、解決什麼問題——從票裡抄，subagent 看不到票外討論>。

【共通規則】先讀 docs/harness/templates/implement.md 的〈共通規則〉並照做（不要在這裡重寫）。

【範圍與邊界】
- 預期動的檔案：<清單或目錄>
- 明確不要動：<如「不動既有 migration」「不改 API 對外格式」>
- 遵守 AGENTS.md；使用者可見功能同步各介面與 docs/SPEC.md。

【驗收條件】
1. <可驗證條件1>
2. <條件2...>
3. `make <對應檢查>` 全綠。

【回報格式】
- 變更摘要：檔案:行號 ＋ 每檔一句話為什麼。
- 驗收自查：逐條 ✅/❌ 附證據（測試輸出關鍵行）。
```

實作完成 ≠ 完成：主對話仍須派 review.md 獨立驗收（dispatch.md「驗證不自驗」）。

## 共通規則（子代理開工第一件事讀這節；派工 prompt 只寫「依本節＋這張票的差異」，不要每次重貼）

> 由來（源專案 v4.81.0）：一個 session 派了十幾次實作代理，每次都重貼 40～60 行同樣的規則。
> 那是輸出 token（貴又慢）。寫在這裡一次，prompt 只引用。

**工作區與範圍**
- 只在 prompt 指定的工作區工作，**一律絕對路徑**；不碰主目錄與其他工作區、不 checkout stage、不 merge、不推 stage、不部署（啟用 `make hooks` 的 clone，commit 後會自動把 feature 分支推到 origin，是預期的）。
- 不動 `docs/SPEC.md`（只在合流 stage 時寫）；實際行為改變寫進票的〈開發備註〉。
- 不發明票外規則、不在畫面加票上沒有的說明文字；需求不明就選票上的預設並在回報註明。權限對應（各角色能看能改什麼）寫進開發備註「待使用者確認」，不自己選邊；票上已有回答的「欄位權限：」「誰能改：」就照票。
- 動畫面層檔前先用 Skill 工具啟動 `ui-design`（閘門會擋，不要 override）——讀 `.agents/skills/ui-design/SKILL.md` 核心，再照它的對照表讀 `references/` 對應那幾份，拿不準就讀，只是不要沒事全讀；使用者看得到的文字先啟動 `ux-writing`。

**git**
- commit 只 `git add` 指名到檔案（不用 -A、`.`、資料夾）；訊息末尾加 Co-Authored-By 行（用主對話系統提醒給的那一行）。
- 有序號的檔（例如資料庫 migration）取號前先 `git fetch origin`、對 origin/stage 與各遠端分支確認；已部署的不刪檔。

**測試與環境**
- 你同時只能跑 1 個測試程序；平常只跑新增與直接相關的測試，整套只在交件前跑一次（輸出導檔再讀，不要接 `| tail`）。
- 檢查要**親眼看到「通過／OK」字樣**，輸出不要接管線。
- 測試走真入口（真實頁面、真實 API），斷言寫使用者看得到的結果；交件前做**破壞版驗證**（拿掉你的修改，新測試要紅；先提交再做）。
- **測試裡的時間別寫死「今天某個鐘點」**：凌晨跑會變成「還沒開始」。開始時間用當天 00:00，日期用專案時區的今天。
- 內建瀏覽器一次只讓一位用（同一個瀏覽器共用 cookie，多人同時用會互相登出）；其他人用 HTTP client＋session cookie 驗證。
- 測試：`make test-crawler`、`make test-server`（Django 測試用自己的暫存資料庫，不碰 `server/db.sqlite3`）、`make lint-web`。
  環境：後端 `server/manage.py runserver 127.0.0.1:8000`、前台 `npm --prefix web run dev`（埠 3000）；
  每棵工作區有自己的 `server/db.sqlite3` 與 venv，不共用。爬蟲連線測試用 `--limit` 少量抓，不要整批重抓。

**回報格式**（≤ 25 行，diff 留在工作區不貼）：逐條驗收 ✅/❌＋證據（測試名稱與結果）；「實際驗證過／只讀過」分開寫；沒跑到的關卡明講；假設與待使用者確認事項；commit 雜湊。被環境卡住（服務起不來、資料庫連不上）立刻停下回報，不要硬繞。

> 驗收員（review.md）的共通限制同上：不改程式檔、不 commit、不碰共用資料庫；**只對碰權限、金額、隱私、狀態判斷的票派**（見 dispatch.md「驗證不自驗」）。
