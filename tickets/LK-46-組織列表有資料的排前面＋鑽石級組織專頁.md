## 目的（要解決什麼問題）

收錄的十萬個組織裡，只有約 4,600 個在組織頁上看得到任何紀錄，其餘只有財政部名冊的名稱、統編、縣市。
首頁列表與搜尋結果常被這些「點進去什麼都沒有」的組織佔滿，捐款人找不到值得看的。
另外，資訊公開最完整的鑽石級組織沒有一個地方集中呈現。

## 使用角色與情境

- 捐款人／一般大眾：在首頁瀏覽或搜尋組織時，先看到有紀錄可查的；想找「公開資訊做得最好」的組織時，有一頁鑽石級名單可看。

## 逼問紀錄

- 問：沒資料的組織要不要從前台隱藏？／答：使用者 2026-11-28「還是要可以搜尋的到，但是在推薦上面，優先推薦那些有資料的」／因此：不隱藏，改成每一種排序都把有資料的排前面。
- 問：要不要有一頁專門列鑽石級？／答：使用者 2026-11-28「有一頁特別標註那些鑽石級的組織，可以公開爬的到資訊等等」／因此：新增 /diamond。

## 需求細節

- 「有資料」＝組織頁上看得到任一種紀錄：近 5 年的勸募申報、勸募活動或群眾集資、政府補助、財務報告、年報／工作報告、捐款，或任何一筆裁罰（裁罰永久保留，不看年度）。只有基本資料（財政部名冊、分類、法人登記公告）的不算。
- 存成組織的 `has_data` 欄位，跟揭露層級一起由 `recompute` 重算（每天 05:30 全部重算、抓完資料後重算被動到的、容器啟動時重算）。
- 組織列表 API 每一種排序（公開募款、揭露層級、名稱）都先排有資料的；沒資料的照樣搜得到、篩得到，排在最後。
- 組織列表 API 新增 `level` 篩揭露層級；`/api/stats` 新增 `with_data`、`diamond`。
- 首頁統計卡：「收錄組織」改成「有紀錄可查的組織」，「近 5 年有公益勸募紀錄」改成「鑽石級組織」（連到 /diamond）；「近 5 年受裁罰」不變。列表上方「共 N 個組織」仍是全部。
- 新頁 /diamond「鑽石級組織」：一句說明＋連到資料說明的揭露層級段落；列表沿用首頁的列（共用元件 OrgRows），依近 5 年公開募款排序、每頁 20 個；沒有組織時顯示空狀態。頁尾連結加「鑽石級組織」。
- 欄位權限：不涉及（`has_data` 只用來排序、不在 API 輸出；層級與統計原本就公開）。

## 這次可能會弄壞什麼

- W1 首頁組織列表：三種排序、搜尋、縣市／分類篩選、分頁
- W2 首頁統計卡（手機三欄）
- W3 首頁探索區與領域區（共用同一份列表元件前後）

## 驗收標準

- [x] W1 依名稱排序第 1 頁都是有資料的組織；只有基本資料的組織用統編搜得到
- [x] W1 依揭露層級、依公開募款排序照舊，有資料的在前
- [x] W2 統計卡顯示有紀錄可查的組織、鑽石級組織（可點）、近 5 年受裁罰，手機不破版
- [x] W3 探索區照常顯示（首頁第 1 頁）
- [x] /diamond 列出鑽石級組織；沒有時顯示空狀態
- [ ] prod 上線重算後，has_data 組織數跟〈條件確認〉一致

## 邊界（明確不做什麼）

- 不隱藏任何組織，組織頁照常可看。
- 不改揭露層級的算法。
- 分類篩選旁的組織數（taxonomy 計數）仍算全部組織，不改。
- 頁首主選單不加鑽石級（手機空間不夠），放頁尾與首頁統計卡。
