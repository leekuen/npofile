## 目的（要解決什麼問題）

LK-02 只接了兩個政府來源。架構圖還列了智邦公益館、一起夢想、集資平台（嘖嘖、挖貝）、組織官網／臉書、司法院裁判書與行政裁罰查詢；接上之後捐款專案與裁罰資料會更完整。

## 使用角色與情境

- 管理員／編輯：在後台啟用新來源；這些非官方來源抓回來的資料預設進待審核清單。

## 逼問紀錄

- 問（agent 代決）：司法院裁判書能不能直接抓？／答：司法院資料開放平臺的裁判書 API 要先註冊帳號取得 Token，而且只在每天 00:00～06:00 提供服務；裁判被移除時要同步刪除／因此：需要使用者先註冊帳號，動工前要拿到帳號。
- 問（agent 代決）：臉書能不能抓？／答：臉書禁止未經授權的爬取，要走官方 Graph API 與審核／因此：這張票先不含臉書，除非有 API 權限。
- 問（agent 代決）：非官方來源要不要自動上架？／答：不要，預設進待審核／因此：沿用 LK-02 的審核機制。

## 需求細節

- 逐一評估並接上：智邦公益館、一起夢想、嘖嘖、挖貝、組織官網徵信頁、司法院裁判書 API（需帳號）。
- 每個來源都走 LK-02 的爬蟲架構與審核佇列，預設「需人工審核」。
- 欄位權限：沒有新欄位出現在新地方或開給新角色（這張票只增加資料來源，資料照 LK-01／LK-02 的權限顯示）。
- 誰能改：只有管理員／編輯。
