## 目的（要解決什麼問題）

靠人工一筆一筆輸入十萬個組織不可能，要讓程式自動去公開的政府資料抓，抓回來的東西先進「待審核」，管理員確認後才上架（架構圖：後台 →「爬蟲機制設定／審核機制設定」→ 送回後台）。

## 使用角色與情境

- 管理員／編輯：在後台設定每個資料來源要不要啟用、抓回來要「自動上架」還是「進待審核」；在後台看待審核清單，一筆一筆或整批核准、退回；看每次爬蟲跑了多少、成功失敗幾筆。
- 系統：每天定時跑爬蟲（正式環境用排程器呼叫指令）。

## 逼問紀錄

<!-- 使用者 2026-11-27 指示「全力開發，自己判斷、自己搜尋」，以下全部是 agent 代決。 -->

- 問（agent 代決）：先接哪些來源？／答：①衛福部「公益勸募管理系統」sasw.mohw.gov.tw/app39 的勸募團體頁（一頁就有基本資料、歷年募款、歷年活動、近五年裁處資訊，四類資料都有）②財政部「非營利事業機關團體資料集」CSV（約十萬個組織的統編、名稱、縣市、異動狀態）／因此：架構圖四類資料各有一個可抓的官方來源；集資平台、司法院、臉書與官網另開 LK-05。
- 問（agent 代決）：會不會違反網站規範？／答：兩個都是政府公開資料（財政部那份是政府資料開放平臺授權）；公益勸募系統沒有 robots.txt 限制。爬蟲每秒最多一個請求、帶固定的 User-Agent，失敗不狂重試／因此：不對來源網站造成負擔。
- 問（agent 代決）：審核機制怎麼設計？／答：每個來源一個開關「自動上架／需人工審核」，管理員在後台可改。兩個政府來源預設自動上架；之後的非官方來源（LK-05）預設需人工審核／因此：見〈條件確認〉。
- 問（agent 代決）：同一個組織兩個來源都有資料，衝突時聽誰的？／答：以統編合併；基本欄位「後抓到的非空值蓋掉舊值」，但管理員在後台手動改過的欄位不被爬蟲蓋掉／因此：管理員的修正不會隔天被洗掉。
- 問（agent 代決）：財政部名冊裡的已註銷、已撤銷、擅自歇業的要不要收？／答：收，但標營運狀態，不隱藏／因此：查「這個組織還在不在」也是透明度的一部分，而且不需要多一條隱藏條件。

## 需求細節

- 爬蟲程式放 `crawler/`（不依賴後台框架，只負責「抓網頁 → 解析成整齊的資料」），由後端的指令 `python manage.py crawl <來源>` 呼叫並寫進資料庫。
- 來源一：財政部非營利名冊 `https://eip.fia.gov.tw/data/BGMOPEN99.csv` → 組織的統編、名稱、所在縣市、營運狀態（依「最近異動原因」：註銷稅籍→已註銷、撤銷登記→已撤銷、擅自歇業→擅自歇業，其餘→營運中）。
- 來源二：衛福部公益勸募系統 → 從團體列表頁一頁頁找出團體，再進每個團體頁抓：統編、團體類型、電話、官網、登記／聯絡地址、勸募用途、歷年募款（年度／實募／預募）、歷年活動（名稱、預募、實募、成果備查日期、結案備查日期、活動頁網址）、近五年裁處資訊（處分日期、處分內容、罰鍰）。可指定只抓前 N 個團體（測試與分批用）。
- 每次執行留一筆「爬蟲執行紀錄」：來源、開始／結束時間、抓到幾筆、新增幾筆、待審幾筆、失敗幾筆、錯誤訊息。
- 抓回來的每一筆先存成「爬蟲資料」：來源、資料類型、統編、內容、狀態（待審核／已核准／已退回／已自動上架）、比對到的組織。
  - 來源設定為自動上架 → 直接寫進組織資料，狀態記「已自動上架」。
  - 需人工審核 → 狀態「待審核」，管理員在後台核准後才寫進組織資料；退回則不寫。
  - 同一筆內容（同來源、同統編、同類型、內容相同）重抓不重複建立。
- 管理員在後台手動改過的基本欄位，記下「手動鎖定」，爬蟲不覆蓋。
- 後台：來源設定頁（啟用、自動上架開關、每次最多抓幾筆、說明）、待審核清單（可批次核准／退回、可看原始內容與來源網址）、執行紀錄清單；來源設定頁有「立即試跑（少量）」動作，方便測試。
- 欄位權限：爬蟲資料、執行紀錄、來源設定都是新的，原本沒有 → 做完：只有管理員在後台看得到、能改；不出現在前台與任何對外 API。核准後的資料照 LK-01 的權限出現在前台。
- 誰能改：只有管理員／編輯。

## 這次可能會弄壞什麼

- W1 後台組織編輯頁（LK-01）：爬蟲寫入的資料要能在原本的組織編輯頁正常顯示、修改。

## 驗收標準

- [ ] W1 後台打開一個爬蟲抓進來的組織，四類資料都看得到，手動改一個欄位存檔成功，再跑一次爬蟲該欄位不被改回。
- [ ] 用解析程式對存下來的真實網頁（有裁罰、無裁罰、團體列表各一份）做自動化測試，抓出的統編、地址、歷年募款、活動、裁罰欄位都正確。
- [ ] 跑 `crawl fia` 匯入財政部名冊後，組織數與檔案有效列數一致，已註銷的組織營運狀態正確。
- [ ] 跑 `crawl mohw --limit 20` 實際連線抓 20 個團體成功，執行紀錄有正確的計數。
- [ ] 把來源改成「需人工審核」再跑，資料停在待審核清單、前台看不到；核准後才出現；退回的不出現。
- [ ] 重跑同一來源不會產生重複資料。

## 邊界（明確不做什麼）

- 不接集資平台、司法院裁判書、臉書、組織官網（LK-05）。
- 不做排程器本身（正式環境用系統排程呼叫指令，部署時再設）。
- 不抓勸募活動的 PDF 附件內容。

- 動工宣告：全清單走查（狀態流程：是——待審核／已核准／已退回／已自動上架）。

- 決策調整：公益勸募頁的裁處卡片沒有寫處分機關，原本填的「衛生福利部或地方主管機關」是推測，已拿掉、留空。
