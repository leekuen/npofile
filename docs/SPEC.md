## 0. 這份文件是什麼

用非工程師也讀得懂的方式，描述本專案**目前**提供哪些使用者可見功能。功能改了就要更新本文件——
**寫點在合流 `stage` 的那一次**（feature 分支與開票階段不動它；還沒上 `stage` 的規劃住在票裡）。

### 狀態圖例

| 狀態 | 意義 |
|------|------|
| ✅ 已完成 | 已實作、所有介面到位並通過驗證，可用。 |
| 🚧 進行中 | 已上 `stage`，但尚未驗收或功能未完整。 |
| ⏳ 未開始 | （舊制）已規劃但尚未動工。**不再新增**——還沒上 `stage` 的功能不寫進本文件；既有的 ⏳ 列在該功能上線或作廢時順手處理。 |

## 1. 產品概述

- **一句話定位**：讓大眾查得到非營利組織的受捐紀錄、資金來源（財閥／金主），以及受裁罰紀錄的公開透明平台。
- **主要角色**：
  - 公眾／捐款人（查詢者）：查詢非營利組織的受捐、資金來源、裁罰紀錄。
  - 非營利組織（被查詢對象）：資料主體，本身不一定登入系統。
  - 管理員／編輯（資料維護）：負責輸入／審核捐款、金主、裁罰等資料的幕後人員。
- **範圍邊界**：目前收錄政府公開來源（衛福部公益勸募管理系統的團體頁、勸募活動、捐贈人清冊、違規公告；財政部非營利事業機關團體資料集；經濟部商工登記；衛福部主管對民間團體及個人補(捐)助經費彙總表）；
  募款、專案、捐款只收近 5 年（民國年度今年往前 4 年起），裁罰全部年度；
  群眾集資平台已接挖貝 WaBay（LK-15；嘖嘖有機器人驗證不接）；司法院裁判書、臉書與組織官網尚未接（LK-05）。不做金流、不寄信（沒有 Email 驗證與忘記密碼）、尚無正式部署環境。

## 3. 功能細節

> 每個功能一節：誰用、入口在哪、操作流程、規則與邊界、驗收標準。
> 對應的功能票在 frontmatter `spec:` 欄位指回本節（例：`spec: docs/SPEC.md#31-xxx`）。

### 3.1 管理員後台（組織資料 CRUD）🚧

- **誰用**：管理員／編輯，電腦瀏覽器，`/admin/`（後端網址）。只有管理員帳號進得去，捐款人帳號會被擋。
- **資料**：組織（統一編號 8 碼為唯一識別、名稱、團體類型、負責人、地址、電話、官網、縣市、勸募用途、營運狀態：營運中／已註銷／已撤銷／擅自歇業），
  底下四類：年度募款、捐款紀錄（可標匿名）、捐款專案、受裁罰紀錄；每筆都記來源名稱與網址。
- **操作**：依統編或名稱搜尋，依營運狀態、縣市、團體類型篩選；組織頁內一起編輯四類資料。
- **規則**：管理員改過的基本欄位自動「手動鎖定」，爬蟲不覆蓋；「解除手動鎖定」動作可解開。匿名捐款在前台與 API 一律顯示「匿名」。

### 3.2 爬蟲與審核佇列 🚧

- **誰用**：管理員；正式環境由排程呼叫 `manage.py crawl <來源>`。
- **來源**（`crawl <代號>`）：
  - `fia` 財政部非營利名冊（統編、名稱、縣市、營運狀態）；
  - `mohw` 衛福部公益勸募團體頁（基本資料、近 5 年年度募款、最近幾筆勸募活動、近五年裁處）；
  - `mohw_activities` 近 5 年的勸募活動（期間、許可文號、地區、用途）與捐贈人清冊（見 3.5），依勸募年度列出、每晚接著上次進度抓（LK-13）：
    先抓沒抓過的（去年往前，再今年、明年）；列表上實募金額變了才重抓清冊；還沒有清冊的，活動結束未滿 12 個月每 7 天再看一次；
    申請單位用名稱對到團體（同名只有一個才算，對不到的跳過、30 天後再試）。過去年度的列表 7 天翻一次。`--limit` 算活動數；
    `--group <編號>` 可只抓指定團體；
  - `mohw_violations` 違規公告總表（所有年度的裁處：處分機關、文號、內容、罰鍰、處分理由），依團體名稱查出統編。
  - `wabay` 挖貝群眾集資（LK-15，非官方、預設先審核、跟 `crawl all` 跑）：只照 robots.txt 抓 `/projects` 列表與專案頁，只存名稱、提案者統編、金額、人次、期間、網址（不存文案與圖片）；
    提案者統編不在組織資料庫的跳過（執行紀錄備註「跳過 N 筆」）；核准過的同一專案之後的金額更新直接上架；列表只有進行中的專案，已收過的「長期集資」或結束未滿 14 天的會回頭再看。
  - `mohw_grants` 衛福部主管「對民間團體及個人補(捐)助經費彙總表」（LK-19，政府來源、自動上架、跟 `crawl all` 跑）：政府資料開放平臺 dataset 44952，近 5 年每年取季數最大的累計表（CSV，舊年度 ODS）；
    受補助對象名稱跟組織名稱完全相同且唯一才收（去空白、臺＝台），去掉結尾括號再比，「X附設Y」「X附屬Y」歸給 X 並記附設單位；同一案件（年度＋機關＋對象＋事項＋最早核准日）跨季更新同一筆。
  - `esf_grants` 勞動部就業安定基金「對民間團體及個人之補(捐)助情形季報表」（LK-24，dataset 128781，規則同 `mohw_grants`）；兩個來源都由 `crawler/npofile_crawler/grants.py` 的 `DatasetSpec` 設定，加部會多一行設定。
  - LK-30 再加四個（規則同 `mohw_grants`，政府來源、自動上架、跟 `crawl all` 跑）：`k12ea_grants` 教育部國民及學前教育署（dataset 48670，111 年起的「截至第 N 季止…彙總表」）、
    `wda_grants` 勞動部勞動力發展署及所屬（dataset 143623；公務預算、特別預算各取一份，「對個人」的列不收，受補助對象前面黏的「某某分署」切下來當補助機關）、
    `nidf_grants` 新住民發展基金（dataset 86171，只拿「個人及團體」那份）、`oac_grants` 海洋委員會（dataset 139265 只有一份清單，照連結進公告頁拿 ODS 附件；111、112 年只有 PDF，讀不到）。
    組織頁的補助清單：不同來源列了名稱＋事項＋核准日＋金額都相同的一筆（例：勞發署跟就業安定基金）只算一次。
    不接的：內政部 106562（ZIP 裡只有 PDF）、國產署 62593（每季都是 0 元）、勞發署舊制 45215（只到 109 年第 1 季，在近 5 年外）。
  - `tpe_labor` 臺北市政府勞動局「違反勞動基準法事業單位及事業主公布總表」（LK-29，政府來源、自動上架、跟 `crawl all` 跑）：dataset 121435（每月更新的整份 CSV，所有年度）；
    只收名稱含財團法人／社團法人／基金會／協會／學會、或名稱對得上組織的列（對組織規則同 `mohw_grants`），一般公司行號不收；**負責人姓名不讀不存**。
    寫進受裁罰紀錄（處分日期、處分機關、處分字號、違反條款＋內容、罰鍰、備註當處分理由）；同一筆＝處分機關＋字號＋名稱，更新同一筆。
    名稱像非營利組織但對不上的，統編空白留在審核佇列：篩「對組織：對不上組織（待指定）」，在「對應組織」指定後核准，或退回略過。
    縣市由 `crawler/npofile_crawler/labor.py` 的 `LaborSpec` 設定，加縣市多一行設定（目前只有臺北市）。
  - `mol_labor` 勞動部「違反勞動法令事業單位（雇主）查詢系統」（LK-37，政府來源、自動上架、跟 `crawl all` 跑，30 天內成功過就略過）：announcement.mol.gov.tw，
    依關鍵字（財團法人、社團法人、基金會、協會、學會、促進會、教會、聯合會、總會）下載各法規組別的 CSV，全國各縣市勞動局、勞保局、職安署的處分；
    名稱欄「單位名稱(負責人)」的**負責人姓名在解析時切掉、不存**；對組織規則同 `tpe_labor`，「財團法人○○附設○○」算給上層法人；對不上的進審核佇列。
    同一筆＝處分字號＋單位名稱（勞保局一張處分書會列很多單位）；跟 `tpe_labor` 用處分字號雙向去重。勞退加徵滯納金照收、內容寫明「加徵滯納金」。
  - `moenv_penalties` 環境部「列管事業污染源裁處資料」（LK-36，政府來源、自動上架、跟 `crawl all` 跑；要在 `server/.env` 設 `MOENV_API_KEY`，到 data.moenv.gov.tw 免費申請，沒設就略過、不算失敗）：
    API `ems_p_46`，用統一編號對組織，**只收站上已有的組織**，對不上的不存、不進審核佇列；**違規人名稱與地址不存**。第一次全部回補，之後從上次讀完那天往前 120 天起只抓新匯入的。
    寫進受裁罰紀錄（處分日期、處分機關（縣市環保局全名，縮寫照對照表補全）、裁處書字號、違反法條、主旨當內容、罰鍰、違規事實當處分理由，有訴願結果附在後面）；同一筆＝管制編號＋字號。
  - `pcc_debarment` 行政院公共工程委員會「拒絕往來廠商公告」（LK-41，政府來源、自動上架、跟 `crawl all` 每天整份讀一次，不需金鑰）：dataset 5988 的 JSON，
    用統一編號（補滿 8 碼）對組織，**只收站上已有的組織**，個人廠商與對不上的不存、不進審核佇列；**負責人、身分證、聯絡人、地址不存**。
    寫進受裁罰紀錄（生效日當處分日期、公告機關、案號、「停權 N 年（起～迄），政府採購法第 101 條第 1 項第 N 款」當內容、案名與申訴結果當處分理由），類別「政府採購停權」；
    同一筆＝統編＋案號＋案名＋生效日。到期後名單上會消失，站上照 LK-07 永久保留，內容看得出停權到哪天。
  - **裁罰類別**（LK-36）：存在受裁罰紀錄的「類別」欄位：公益勸募、勞動法令、環境保護、政府採購停權；爬蟲寫明的為準，沒寫的來源名稱含「勞動」算勞動法令、其餘公益勸募。後台可改類別與違反法條。
  - `judicial` 司法院「法人登記公告」（LK-31，政府來源、自動上架、跟 `crawl all` 跑）：只請求 www.judicial.gov.tw 的列表與內頁（不碰 robots 禁止的 aomp109）；
    存法院、登記案號與號數、類別（社團／財團）、案由（設立／變更／解散／清算人任免或變更／清算終結）、公告與登記日期、財產總額、變更事項類別；**董事、監察人與其他人名不存**。
    同一筆＝法院＋登記案號；108-12-10 起全部保留，第一次回補、之後每天只抓新的。名稱對組織規則同 `mohw_grants`，同名多個用法院管轄縣市挑；
    對不到的也存（`orgs.CourtRegistration` 組織可空，後台可手動指定），只有對到的才抓內頁，每晚 `match_court_registrations` 重新比對並補抓內頁。不改財政部名冊的營運狀態、不算揭露層級。
  - `moe_registry` 教育部主管教育財團法人名冊（LK-32，dataset 117679）、`einvoice_codes` 電子發票受捐贈機關團體捐贈碼（LK-32，dataset 31868）：政府來源、自動上架，`crawl all` 距上次成功不到 30 天就略過（每月檢查）。
    名冊只讀主管機關、設立許可文號、設立日、許可設立與最新登記財產、宗旨、主要業務、服務對象、業務類別、名冊狀態（**董事長、執行長、聯絡人姓名與聯絡方式不讀**），名稱對組織規則同 `mohw_grants`（附設單位不算），對不上的存著不顯示、後台可指定（`orgs.RegistryEntry`）；
    捐贈碼用清單上的統編在讀取時對組織（`orgs.DonationCode`）。兩者不改財政部名冊欄位、不算揭露層級與分類。
  - `orgsite` 組織官網的年報與財務報告（LK-17，非官方、預設先審核、跟 `crawl all` 跑）：有官網（不是臉書、IG、表單、短網址）的組織，從沒爬過、再來最久沒爬的先；
    從首頁跟著「財務、年報、資訊公開、徵信」這類同站連結最多走兩層、每站最多 20 頁、遵守 robots.txt；PDF 與 Google 雲端檔依標題、網址、外層表格列判斷年度與種類
    （財務報告／年報／工作或成果報告；工作計畫、預算、徵信與捐款名單不收，單一勸募活動的收支表算成果報告），只收近 5 年；靠 JavaScript 才出現的網站抓不到。
    `server/.env` 設了 `ANTHROPIC_API_KEY` 才下載報告、交給 Claude（預設 `claude-opus-5-5`，`FINANCIAL_EXTRACT_MODEL` 可換）讀出年度財務數字，每年讀一份（財務報告優先、其次年報），同一份讀過不再讀；
    沒設只收報告清單。「每次最多抓幾筆」算組織數；讀數字會產生 API 費用。規則在 `crawler/npofile_crawler/orgsite.py`、`financials.py`。
  - `swft` 衛福部社家署「社會福利民間資源友善查詢網」全國性社福財團法人年度決算（LK-25，官方、自動上架、跟 `crawl all` 跑）：清單一頁 12 筆跟網站一樣；
    每家每年印「年度決算總表」PDF，讀本會收支餘絀表（不含附屬作業組織那張）的收入合計、捐贈收入、服務收入、支出合計、業務支出、行政管理支出、本期餘絀，

  - `twnpos` 台灣公益團體自律聯盟「好事大平台」會員財務報告（LK-25，非官方、先審核、預設每次最多 120 分鐘）：會員頁「瀏覽財務報告」的公開雲端資料夾，

  每秒最多一個請求；同內容重抓不重複；5 年前的活動不抓、不下載清冊。清冊下載給 300 秒（衛福部固定先等約 120 秒才給檔，LK-40），單份失敗只跳過那一份；衛福部回空檔（內容 `null`，2026-11-28 起每一份都這樣）記成「衛福部回空檔」，同一輪連續 3 份就這一輪不再下載清冊、只抓活動頁，沒拿到的下一輪再試。
  來源設定可設「每次最多跑幾分鐘」（0＝不限，到時間就停並在執行紀錄備註；勸募活動預設 120 分鐘，約三、四個晚上補齊近 5 年約 4,700 個活動）。
- **維護指令**：`match_companies`（企業捐款人對商工登記統編）、`reclassify_donors`（分類規則改了之後重分，管理員指定的不動）、
  `prune_old_records`（刪掉近 5 年以前的年度募款、專案、捐款、清冊原始紀錄、官網財報與報告，裁罰不刪）、`recompute_scores`；建議每天跑後兩支。
- **審核機制**：每個來源可設「自動上架」或「先審核」（政府來源預設自動上架）。先審核的資料在「爬蟲資料（審核佇列）」，預設只列待審核，可批次核准或退回；核准才寫進組織資料。
  官網報告與年度財務（LK-17）在審核頁以表格顯示（欄位中文名、千分位金額、報告沒列的標「—（報告沒列）」）並附「打開原始報告」，頁底可直接「核准並上架／退回（不上架）／只存審核備註」；
  核准後數字有錯，在組織的「年度財務」改，改過的年度自動鎖住，爬蟲不再覆蓋。
  同一年有多個來源時：政府公開決算 > 讀報告（AI、文字）> 影像辨識，低的不蓋過高的；只有報告連結、沒有數字的誰都可以蓋過（LK-25）。
- **紀錄**：每次執行一筆紀錄（抓到、新資料、上架、待審核、失敗、錯誤訊息、備註）；後台可「立即試跑」每個來源 5 筆。
- **立即完整爬取**（LK-26）：後台「爬蟲來源設定」勾選來源 → 動作「排入完整爬取」，建立一筆「完整爬取請求」；排程每分鐘跑 `run_crawl_requests`，照每晚的方式爬勾選中啟用的來源（停用的略過），再 `prune_old_records`、`recompute_scores`。同一時間只能有一個排隊中或執行中的請求；執行中超過 12 小時標失敗；排隊中的可取消；跑完寫入執行紀錄（最後 2 萬字）。只有後台管理員看得到。
  後台「勸募活動抓取進度」列出每個活動（可篩已抓／還沒抓／對不到），標題顯示「近 5 年活動 N 個，已抓 M 個（有清冊 K 份），還沒抓 R 個，對不到 X 個」。
- **抓到 0 筆算失敗**：來源執行成功卻一筆都沒抓到（多半是網站改版），`crawl` 印警告並以失敗結束，排程會發通知；執行紀錄的狀態仍是成功（LK-12）。
  勸募活動補齊後某晚沒有新的或有變的是正常的，這個來源改看「活動列表一張卡片都沒讀到」才算（LK-13）。

### 3.4 捐款人註冊登入與留言 🚧

- **誰用**：公眾／捐款人；管理員審核。
- **帳號**：Email＋顯示名稱＋密碼（至少 8 碼、不能全數字或太常見）；註冊後直接登入。同 Email 同來源連續 5 次登入失敗鎖 15 分鐘。
- **留言**：組織頁最下方；未登入看到登入連結。送出後作者看到「審核中」，管理員核准後所有人看得到；退回的只有作者看得到「未通過」與原因。
  1～1000 字、每分鐘最多 3 則、作者可刪自己的、不能修改。Email 永不公開。
- **後台**：留言清單預設列審核中，可批次核准／退回；捐款人清單可停用、恢復帳號。

### 3.5 捐贈人清冊與捐款企業 🚧

- **誰用**：公眾／捐款人看；管理員改類型、隱藏。
- **資料**：公益勸募活動成果備查時公開的「捐贈人資料」清冊。名稱分成企業、團體、個人、匿名（含「不公開」「有心人」與 MOMO、LINE Pay、超商等平台彙總）；
  認不出的先當個人。企業名稱與商工登記完全相同時連上統編、代表人、資本額。
- **名稱整理**（LK-16）：去掉看不見的字元、全形換一般寫法、去掉名稱後附的統編與結尾標點；「台」與「臺」、空白、「(股)」與「股份有限公司」、英文大小寫不同的算同一位，匯入時對到既有捐款人（規則只在 `npofile_crawler.donors.identity_key`）。資料庫更新時把既有的重複合成一筆：保留管理員指定類型的、其次有統編的、其次捐款多的；任一筆被隱藏就整筆隱藏。捐款企業搜尋也套用同樣規則；後台改名成另一位的寫法會被擋下。規則改了跑 `merge_donors`。
- **隱私**：個人只在同一活動累計 ≥ 10 萬元（`DONOR_INDIVIDUAL_THRESHOLD`）才存姓名並顯示，且只出現在該組織頁；其餘只留人次與金額。收據編號不公開。
- **組織頁**：企業與團體捐款人排行（可點進企業頁）、大額個人捐款人排行、清冊摘要（清冊合計、其他個人人次與金額、匿名筆數與金額）、捐款明細最近 50 筆。
- **捐款企業** `/donors`：企業與團體依近 5 年捐款總額排行，可搜名稱或統編、篩企業／團體；內頁 `/donors/<編號>`：公司登記、捐給哪些組織、明細。列表每列另寫「支持 N 年・最近 yyy/mm」（LK-38）。
- **捐款概況**（LK-38）：企業頁頁首下方四格——同類排名（企業比企業、團體比團體，依近 5 年總額，同額同名次，附「前 N%」）、持續支持幾個年度、最近一次與第一次捐款、單筆最大；近 5 年裡至少 2 個年度有捐款才出「近 5 年捐款趨勢」折線圖（每年總額，提示框寫捐給幾個組織、幾筆，今年標「至今」）。「捐給哪些組織」每列標支持過的年度，組織有任何裁罰紀錄（不限年份）就標「裁罰 N 筆」連到裁罰分頁；「捐給哪些領域」改名「從捐款看關注議題」放在趨勢圖下方。年度、最近一次只算有日期且不晚於今天的捐款（晚於今天的多半是清冊打錯，照算總額與排名）。不打分數，並註明只涵蓋近 5 年公益勸募清冊。
- **後台**：捐款人清單（改類型會記成「管理員指定」、隱藏後前台哪裡都不出現、金額併入匿名）。

### 3.6 組織分類（兩層領域＋服務對象）🚧

- **分類表**（`server/orgs/taxonomy.py` 唯一出處）：9 個大類——社會福利、教育、文化藝術、醫療健康、環境保護、動物保護、國際援助、人權與公民、非公益類（宗教、公會／產業團體、體育、社區）——各有小類；

  爬蟲匯入後自動重分；`classify_orgs` 全部重算。管理員在後台加上或拿掉的分類，自動分類不改。
- **首頁**：搜尋框下方依大類瀏覽（附組織數，手機一排橫滑），選了大類展開小類；「服務對象」選單；已選條件以標籤顯示可移除；列表每列最多 3 個分類。
- **領域頁** `/categories/<代號>`（大類、小類、服務對象）：組織數、近 5 年公開募款合計、近五年受裁罰組織數；揭露層級最高、近 5 年公開募款最多的組織；支持最多的企業與團體；所有年度的裁罰。
- **組織頁**：名稱下方顯示分類；**企業頁**：「捐給哪些領域」依受捐組織的大類加總（組織屬多個大類時各算全額）。

## 4. 非功能事項

> 效能、資安、相容性等跨功能的承諾與現況；沒有就留空。

- 祕密走環境變數（`server/.env.example`）；正式環境沒設 `DJANGO_SECRET_KEY` 拒絕啟動。登入／註冊檢查 CSRF，前台經同源 `/api/*` 轉給後端。
- 正式環境資料庫為 PostgreSQL（`DATABASE_URL`），目前只驗過設定解析，尚未實際連 PostgreSQL 跑過；本機用 SQLite。
- 部署：DigitalOcean 單機（nginx → Next.js＋gunicorn／Django＋PostgreSQL＋cron），伺服器只拉 `prod`，更新跑 `deploy/deploy.sh`；步驟見 `deploy/README.md`（LK-10）。2026-11-27 起正式站 https://npofile-kuen.duckdns.org，與 LINE CRM 共用同一台 512MB Droplet（CRM 的 Caddy 轉到主機 nginx :8080），做法見 `deploy/README.md`〈與 LINE CRM 共用主機〉。
- Docker Compose 部署（LK-14）：`compose.yaml`（db、backend、web、nginx、scheduler、cloudflared），映像檔支援 linux/arm64 與 amd64；資料路徑用 `.env` 變數（`PG_DATA_DIR`、`BACKUP_DIR_HOST`、`LOG_DIR_HOST`）；對外走 Cloudflare Tunnel 指向 `nginx:80`，主機不開 port；每次推送 GitHub Actions 在 x86 與 ARM64 各整套測一次。`updater`（profile `autoupdate`）每 5 分鐘看 GitHub 的 `prod`，有新版就自己 pull 並重建。步驟見 `docker/README.md`。
- 排程失敗通知：每天的備份、爬蟲、重算都經過 `deploy/run-job.sh`，回報 Healthchecks.io；工作失敗、沒準時開始或沒跑完都會寄信（要設 `HEALTHCHECKS_PING_KEY`，沒設只寫紀錄）（LK-12）。
- 資料庫備份：每天 02:00（爬蟲前）`deploy/backup-db.sh` 用 `pg_dump` 存一份，檢查讀得回來且有組織資料，本機留 14 天；可選用 rclone 複製到機器外（例 DigitalOcean Spaces）留 60 天。還原與每月演練步驟在 `deploy/README.md`（LK-12）。尚未在伺服器上跑過。
- 「近 5 年」只定義在 `server/orgs/period.py`（民國年度今年往前 4 年的 1 月 1 日起），隨日期移動：每天跑 `recompute_scores`、`prune_old_records`。
- 勸募活動「哪些要抓」的規則只寫在 `server/crawling/progress.py`；進度記在資料表 `ActivityProgress`，資料寫進資料庫後才記成已抓，中途停下的下次重抓；至少每分鐘存一次，程式中途被關掉最多白做一分鐘（LK-13 補）。
  每晚爬蟲整段約 2 小時 45 分，Healthchecks 的 `npofile-crawl` 寬限要設 4 小時（`deploy/README.md`）。
- 大型團體的清冊可達十幾萬列（約 3 MB），以串流解析，只存企業、團體與大額個人的逐筆。
