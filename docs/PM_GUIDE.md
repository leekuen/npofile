# PM 指南 — 用 AI Agent VibeCoding

寫給**非工程師**。你不需要懂程式，只要會：打開專案、用一句話說需求、確認驗收。

## 一次性準備

1. 安裝一個 AI Coding Agent（建議 [Claude Code](https://claude.com/claude-code)，
   本框架的自動引導與閘門只在 Claude Code 生效）。
2. 用 Agent 開啟這個專案資料夾。
3. 第一次開啟會自動進入**初始化引導**（如果還沒有人初始化過）：回答幾個問題就好，
   答不出來的可以跳過。

## 每次對話的循環

### 1) 開場
打開新對話，直接說你要做什麼。Agent 會先給你**專案現況簡報**（做完哪些功能、進行中哪些、
有沒有需要你決定的事、這台電腦上還有哪幾個對話在做事），然後**從你的第一句話判斷要怎麼接**，
並在簡報最後一行用白話告訴你接下來要做什麼——它不會停下來問你要選哪個入口。
說的不對，直接回「不對」就好。

### 2) 說需求
用你的話說就好：

> 我想要讓客戶可以線上預約。

Agent 會反問你幾件事（這是制度，不是它囉嗦）：**誰會用、要解決什麼問題、怎樣算做好、
這次不做什麼**；如果是全新的頁面或欄位，還會多問一題**誰看得到、誰能改**。
它問你取捨或規則的時候，會用你看得到的情境來問（哪一筆、會交給誰、對方會看到什麼），
不會丟統計或程式術語——看不懂就直接說看不懂。
確認後它會開一張「功能票」——這張票就是開發的依據，之後都可以追溯。

### 3) 請它做
> 直接幫我做出來。

Agent 會自己寫程式、自己檢查，全程用白話回報。畫面類的需求，它可能先給你一張**可以點的示意圖**，
方向對了才真的做。做好後它會**先問你**要不要上測試環境，你同意了它才部署——不會自作主張。

### 4) 驗收
照票上的驗收標準逐條試。過了就跟它說「驗收通過」，它會把票標完成、把功能規格書上那一項改成已完成；
沒過就說哪裡不對，它會回去修。

## 三個你該知道的檔案（都看得懂）

| 檔案 | 內容 |
|------|------|
| `docs/SPEC.md` | 系統**現在**有哪些功能、怎麼運作——跟案主對焦、驗收、報價都用它（功能上了測試環境才會寫進來） |
| `tickets/` | 每張功能票：誰用、目的、驗收標準、進度 |
| `docs/FRAMEWORK.md` | 這套協作制度的規則與歷次變更原因 |

## 常見問題

- **Agent 說「無票不開發」擋住了？** 這是保護機制：先跟它把「誰用/目的/驗收/邊界」
  講清楚、開好票，它就能動工。不要叫它繞過。
- **可以同時開好幾個對話嗎？** 可以。每個對話會在自己的工作區做事，不會互相蓋掉。
  開場簡報會列出每個工作區的狀態，並直接寫出你可以說的話（例：「合 TK-12」「處理 TK-12」「丟掉」）。
- **它說「沒走查」是什麼意思？** 檢查通過之後，它還要照使用者的操作過程實際走一遍。真的走不了的時候，
  它會在回報開頭固定寫三行：**沒走的是什麼、為什麼、誰該補走**。看到這三行，代表那一段還沒有人實際看過。
- **想改制度本身？**（例：加一種角色入口）直接說你想改的規則，它會走 framework 入口。
- **緊急壞掉要修？** 跟它說情況，它會依「救火」流程處理（不改行為的修復不用票；
  修完若行為有變會補票）。
